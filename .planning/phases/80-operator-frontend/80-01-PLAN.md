# Plan 01: Backend — Camion CRUD, assign commande, list feuilles

## Goal
Create Camion model with CRUD, add camion assignment to commandes, expand feuilles de route endpoints to support the operator dashboard.

## Tasks

<task id="01.1">
### Create Camion model and migration

<read_first>
- apps/api/app/models/document.py (FeuilleDeRoute — camion_id is currently string)
- apps/api/app/db/base.py (AuditMixin, Base)
- apps/api/app/models/__init__.py
</read_first>

<action>
1. Create `apps/api/app/models/camion.py`:
   ```python
   from uuid import UUID, uuid4
   from sqlalchemy import String, Uuid
   from sqlalchemy.orm import Mapped, mapped_column
   from app.db.base import AuditMixin, Base

   class Camion(AuditMixin, Base):
       __tablename__ = "camions"
       id: Mapped[UUID] = mapped_column(Uuid, primary_key=True, default=uuid4)
       nom: Mapped[str] = mapped_column(String(100), nullable=False)
       plaque: Mapped[str] = mapped_column(String(20), unique=True, nullable=False)
   ```

2. Update `apps/api/app/models/__init__.py` to import Camion

3. Create Alembic migration:
   ```bash
   cd apps/api && alembic revision --autogenerate -m "add camion table"
   ```

4. Update `FeuilleDeRoute.camion_id` from `String(50)` to `Uuid, ForeignKey("camions.id")` in the model.

5. Add `camion_id: Mapped[UUID | None]` to `Commande` model (nullable FK to camions).

6. Create migration for the FK changes:
   ```bash
   alembic revision --autogenerate -m "add camion fk to commandes and feuilles_route"
   ```

7. Run migrations: `alembic upgrade head`
</action>

<acceptance_criteria>
- apps/api/app/models/camion.py contains class Camion with id, nom, plaque
- Camion has AuditMixin (created_at, updated_at, created_by)
- Commande model has camion_id nullable FK
- FeuilleDeRoute.camion_id is UUID FK to camions
- `alembic upgrade head` exits 0
- `ruff check apps/api/` exits 0
</acceptance_criteria>
</task>

<task id="01.2">
### Create Camion CRUD endpoints

<read_first>
- apps/api/app/models/camion.py
- apps/api/app/auth/dependencies.py (CurrentUser, role check pattern)
- apps/api/app/commandes/router.py (pattern for router + schemas)
</read_first>

<action>
1. Create `apps/api/app/camions/__init__.py` (empty)

2. Create `apps/api/app/camions/router.py`:
   - `POST /` — create camion (operatrice/admin only). Body: {nom, plaque}. Returns CamionResponse
   - `GET /` — list all camions. Returns {camions: CamionResponse[], total: int}
   - `GET /{camion_id}` — get single camion
   - `PATCH /{camion_id}` — update camion (nom, plaque). Body: {nom?, plaque?}
   - `DELETE /{camion_id}` — delete camion (check no active feuille de route). Returns 204

3. Schemas (inline in router or separate file):
   ```python
   class CreateCamionRequest(BaseModel):
       nom: str = Field(min_length=1, max_length=100)
       plaque: str = Field(min_length=1, max_length=20)

   class UpdateCamionRequest(BaseModel):
       nom: str | None = None
       plaque: str | None = None

   class CamionResponse(BaseModel):
       id: str
       nom: str
       plaque: str
       created_at: datetime
       model_config = {"from_attributes": True}
   ```

4. Register in `apps/api/app/main.py`:
   ```python
   from app.camions.router import router as camions_router
   app.include_router(camions_router, prefix="/camions", tags=["camions"])
   ```
</action>

<acceptance_criteria>

- All endpoints require operatrice or admin role (except GET list which any authenticated user can access)
- POST /camions creates a camion and returns CamionResponse
- DELETE checks no active feuille de route before deleting
- Router registered in main.py with prefix "/camions"
- `ruff check apps/api/` exits 0

</task>
