## Goal

1. Create `apps/web/hooks/use-dashboard-stats.ts`:

<task id="03.4">
### Build operator order detail page

<read_first>
- apps/web/app/(authenticated)/commandes/[id]/page.tsx (Phase 70 pharmacien detail — pattern)
- apps/api/app/commandes/router.py (accept, reject, assign-camion endpoints)
- .planning/phases/80-operator-frontend/80-UI-SPEC.md (Détail commande opératrice)
</read_first>

<action>
Create `apps/web/app/(authenticated)/dashboard/commandes/[id]/page.tsx`:

1. Fetch order detail: `fetchApi<OrderDetailResponse>(`/commandes/${id}`)`

2. Header: reference_id, StatusBadge, date, **pharmacien name + email**

3. Articles table (same as Phase 70 detail)

4. Total amount

5. **Accept/Reject buttons** (only when statut === "creee"):
   - Accept: `bg-emerald-600 text-white`, direct click → PATCH /commandes/{id}/accept
   - Reject: outline destructive → AlertDialog → PATCH /commandes/{id}/reject
   - After action: toast, refetch order (badge updates)
   - Accept stays on page; reject stays on page

6. **Camion assignment** (only when statut === "acceptee"):
   - Fetch camions list: `fetchApi<{camions: CamionResponse[]}>("/camions")`
   - Select dropdown: "Sélectionner un camion"
   - On select: `PATCH /commandes/{id}/assign-camion {camion_id}`
   - Toast: "Commande assignée au camion {nom}"

7. Back link: "← Retour" to /dashboard
</action>

<acceptance_criteria>
- Page fetches order by id and displays reference, status, date, pharmacien name+email
- Accept button (emerald-600) calls PATCH /accept, no confirmation needed
- Reject button (destructive outline) opens AlertDialog with "Oui, rejeter" / "Non, garder"
- Camion dropdown visible only for acceptee status
- Assign-camion calls PATCH /assign-camion
- Toast "Commande acceptée" / "Commande rejetée" / "Commande assignée au camion {nom}"
- Back link navigates to /dashboard
- `pnpm --filter @dimed/web typecheck` exits 0
</acceptance_criteria>
</task>
