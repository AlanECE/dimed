# Plan 100-03: API security — CORS, rate limiting, validation, headers

## Goal

Harden the API with CORS middleware (explicit origins), rate limiting on login (slowapi), input validation audit on Pydantic schemas, and security headers on Next.js.

## Tasks

<task id="01" title="Add CORS middleware">
<read_first>
- apps/api/app/main.py (current middleware, router setup)
- apps/api/app/config.py (Settings class)
</read_first>
<action>
1. In `apps/api/app/config.py`, add `cors_origins` field to Settings:

```python
cors_origins: list[str] = ["http://localhost:3000"]
```

This is overridable via `DIMED_CORS_ORIGINS` env var. Pydantic-settings parses comma-separated or JSON list.

2. In `apps/api/app/main.py`, add CORS middleware AFTER app creation, BEFORE router includes:

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,
    allow_credentials=True,
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["*"],
)
```

Import `settings` from `app.config`.
Place `add_middleware` between `app = FastAPI(...)` and the first `app.include_router(...)`.
</action>
<acceptance_criteria>
- `apps/api/app/config.py` contains `cors_origins: list[str]` with default `["http://localhost:3000"]`
- `apps/api/app/main.py` contains `from fastapi.middleware.cors import CORSMiddleware`
- Contains `app.add_middleware(CORSMiddleware, ...)` with `allow_credentials=True`
- `allow_origins` uses `settings.cors_origins` (not hardcoded)
- `allow_origins` does NOT contain `"*"` (explicit origins only)
</acceptance_criteria>
</task>

<task id="02" title="Add rate limiting with slowapi">
<read_first>
- apps/api/pyproject.toml (add slowapi dep)
- apps/api/app/main.py (where to add limiter state + exception handler)
- apps/api/app/auth/router.py (login endpoint — target for rate limiting)
</read_first>
<action>
1. Add `slowapi` to `apps/api/pyproject.toml` dependencies:
```
"slowapi>=0.1.9",
```

2. In `apps/api/app/main.py`, add after imports:
```python
from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.errors import RateLimitExceeded
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
```

After `app = FastAPI(...)`:
```python
app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)
```

3. In `apps/api/app/auth/router.py`, add rate limit decorator to login:
```python
from fastapi import Request
from app.main import limiter

@router.post("/login")
@limiter.limit("5/minute")
async def login(request: Request, body: LoginRequest, ...):
```

IMPORTANT: `request: Request` MUST be an explicit parameter for slowapi to work. Check if it's already there; if not, add it as the first parameter.

Note: If circular import issue with `from app.main import limiter`, create a separate `apps/api/app/rate_limit.py` module:
```python
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
```
Then import from there in both main.py and auth/router.py.
</action>
<acceptance_criteria>
- `apps/api/pyproject.toml` contains `slowapi` in dependencies
- `apps/api/app/main.py` or `apps/api/app/rate_limit.py` contains `limiter = Limiter(key_func=get_remote_address)`
- `apps/api/app/main.py` contains `app.state.limiter = limiter` and `app.add_exception_handler(RateLimitExceeded, ...)`
- `apps/api/app/auth/router.py` login endpoint has `@limiter.limit("5/minute")` decorator
- Login endpoint has `request: Request` as explicit parameter
- API starts without import errors
</acceptance_criteria>
</task>

<task id="03" title="Audit and strengthen Pydantic schemas">
<read_first>
- apps/api/app/commandes/schemas.py (CreateOrderRequest, order schemas)
- apps/api/app/auth/schemas.py (LoginRequest)
- apps/api/app/camions/router.py (camion create/update schemas if inline)
- apps/api/app/notifications/schemas.py (notification schemas)
</read_first>
<action>
Audit all Pydantic request schemas and add constraints:

1. `LoginRequest` (auth/schemas.py):
   - `email: str` → `email: str = Field(max_length=254)` (RFC 5321 max)
   - `password: str` → `password: str = Field(min_length=1, max_length=128)`

2. `CreateOrderRequest` (commandes/schemas.py):
   - Article `qte` field: ensure `qte: int = Field(ge=1, le=10000)`
   - Articles list: `articles: list[...] = Field(min_length=1, max_length=100)`

3. Camion schemas (if exist):
   - `nom: str` → `nom: str = Field(min_length=1, max_length=100)`
   - `plaque: str` → `plaque: str = Field(min_length=1, max_length=20)`

4. General: verify all string fields have `max_length` to prevent oversized payloads. UUIDs are already validated by Pydantic's `UUID` type.

Import `Field` from pydantic where needed.
</action>
<acceptance_criteria>
- `LoginRequest` has `max_length` on email and password fields
- `CreateOrderRequest` article `qte` has `ge=1`
- `CreateOrderRequest` articles list has `min_length=1`
- All string fields in request schemas have `max_length` constraints
- `Field` imported from pydantic in modified schema files
- API starts without validation errors on existing requests
</acceptance_criteria>
</task>

<task id="04" title="Add security headers to Next.js">
<read_first>
- apps/web/next.config.ts (current config)
</read_first>
<action>
Update `apps/web/next.config.ts` to add security headers:

```typescript
import type { NextConfig } from "next";

const securityHeaders = [
	{ key: "X-Content-Type-Options", value: "nosniff" },
	{ key: "X-Frame-Options", value: "DENY" },
	{ key: "X-DNS-Prefetch-Control", value: "off" },
	{ key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
];

const config: NextConfig = {
	transpilePackages: ["@dimed/shared-types", "@dimed/ui"],
	output: "standalone",
	async headers() {
		return [
			{
				source: "/(.*)",
				headers: securityHeaders,
			},
		];
	},
};

export default config;
```

Note: `output: "standalone"` may already be added by plan 100-02. If so, just add the `headers()` function. Don't duplicate `output`.
</action>
<acceptance_criteria>
- `apps/web/next.config.ts` contains `async headers()` function
- Headers include: X-Content-Type-Options nosniff, X-Frame-Options DENY, X-DNS-Prefetch-Control off, Referrer-Policy strict-origin-when-cross-origin
- Headers apply to source `"/(.*)"` (all routes)
- Config still has `transpilePackages` and `output: "standalone"`
</acceptance_criteria>
</task>

